# Quantum Compass Landscape Fingerprint Model Card

## Model identity

- **Model:** RandomForestClassifier
- **Artifact:** `data/fingerprint_model.pkl`
- **Feature contract:** 16 landscape-shape features in `core.fingerprint.FINGERPRINT_FEATURE_NAMES`
- **Default classes:** `ideal`, `earth-lab`, `leo-satellite`, `satellite-ground`, `meo-van-allen`, `deep-space`
- **Default training design:** 50 simulated landscapes per class, four logical qubits, depth `p=1`, `9×9` gamma-beta grid
- **Purpose:** distinguish the project's own controlled simulated noise families from QAOA landscape shape

## Intended use

The model is a diagnostic aid for questions such as:

- Is an uploaded QAOA landscape more consistent with the project's Earth-lab, LEO, link-loss, radiation-belt, or deep-space simulator profile?
- Is a calibration/simulation surface visually and statistically closer to one controlled reference family than another?
- Which follow-up channel parameters should be inspected first?

It is suitable for interactive exploration, software tests, and hypothesis generation.

## Non-intended use

It must **not** be used as:

- forensic attribution of an arbitrary physical quantum processor;
- evidence that a device is operating in a named orbital environment;
- a radiation monitor, mission-certification mechanism, or safety decision tool;
- a calibrated probability of an external physical hypothesis; or
- evidence of quantum advantage.

The UI calls its output a model-family prediction and should be read accordingly.

## Training data provenance

Every default sample is generated by Quantum Compass itself through exact Aer landscapes. The classes differ by the channel families specified in `core.noise_models` and deterministic representative-level variations. The training procedure uses the same logical problem scale and simulator implementation as the application.

This provides a controlled software benchmark, not an independent physical dataset. No live IBM Quantum counts, radiation measurements, satellite telemetry, or laboratory calibration stream is included in the default classifier dataset.

## Features

The feature vector includes variance, interior local minima/maxima, peak width, discrete-Laplacian roughness, gradient mean/variance/maximum, symmetry score, range, kurtosis, skewness, histogram entropy, neighbour autocorrelation, peak prominence, and edge-centre contrast.

Features are finite by contract: malformed uploaded surfaces are rejected or normalized before model evaluation. The feature order is a persisted-model contract and is checked before loading a cache.

## Reported controlled validation

The bundled model's deterministic software checks reported:

- OOB score: `1.00`;
- six withheld parameter profiles: `6/6` correctly classified; and
- five curated mystery landscapes: `5/5` correctly classified.

These values assess interpolation within the controlled simulator family only. They should not be generalized to novel graph distributions, different depths, hardware compilations, shot-noisy landscapes, correlated error processes, or physical devices.

## Known limitations and likely failure modes

1. **Closed-set labels:** every prediction must be assigned to one of the known classes, even if an input belongs to none of them.
2. **Limited topology diversity:** the default training protocol is intentionally small and computationally affordable; it does not establish graph-family invariance.
3. **Resolution/depth shift:** uploaded landscapes at a different resolution or QAOA depth can alter extrema/gradient features.
4. **Shot noise and drift:** hardware counts contain finite-shot effects, transpilation effects, drift, crosstalk, leakage, and non-Markovian noise not represented by the default model.
5. **Probability calibration:** RandomForest vote fractions are ranking/confidence scores, not calibrated physical probabilities.
6. **Model-version sensitivity:** a scikit-learn or feature-contract mismatch causes the cache to be regenerated rather than silently reused.

## Required evidence before stronger claims

A future externally credible fingerprint study should use train/test splits that are disjoint in graph topology, depth, resolution, noise parameters, backend date, and compilation strategy. It should compare against real measured counts and use probability calibration, out-of-distribution detection, uncertainty reporting, and a pre-specified evaluation protocol.

The Experimental Validation workflow in `docs/research/experimental_validation_protocol.md` is the first step toward generating the measured data needed for such a study.
